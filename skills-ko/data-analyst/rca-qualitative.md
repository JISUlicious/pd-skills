# 정성적 RCA 기법 — 파레토, 어골도, 5-Why

통계 툴킷을 보완합니다 — 파레토는 중요한 것의 범위를 정하고, 어골도는
후보 원인을 브레인스토밍하며, 5-Why는 검증 가능한 인과 사슬을
구축합니다. **세 가지 모두 후보 생성기입니다. 통계적 검증은 다른 RCA
파일에 있습니다.**

## 목차

- 게이지를 먼저 배제 (MSA) — 결함이 진짜인가?
- 파레토: 무엇부터 해결할 것인가
- Is/Is-Not (Kepner-Tregoe) — 브레인스토밍 전에 문제 범위 정하기
- 어골도 (이시카와, 6M 분류) + 통계적 검증 매핑
- 통계적 반증이 결합된 5-Why
- 결합: MSA → 파레토 → Is/Is-Not → 어골도 → 5-Why → 검증
- 안티패턴

이 파일을 읽는 경우: "실패 모드 백로그가 크다, 어디서부터 시작?",
"데이터 분석 전 가능한 원인 브레인스토밍", "의심되는 인과 사슬이 있는데
각 링크를 어떻게 반증?" 관련 작업. `rca-commonality.md` (Machine /
Material 가지 검증), `rca-causal-analysis.md` (Method 가지 검증),
`root-cause-analysis.md` § 2 (Milieu / 환경 검증)와 함께 사용하세요.

## 게이지를 먼저 배제 (MSA)

이동을 *공정*에 귀속시키기 전에, 그것이 *측정 시스템*이 아닌지
확인하세요. 프로브 교체, 재보정, 새 검사 레시피, 계측 장비 펌웨어
업데이트는 제품에 물리적 변화 없이도 지표를 움직일 수 있습니다. 이것은
베테랑이 모든 이상에 대해 가장 먼저 묻는 질문이며 — 대부분의 데이터
분석이 건너뛰는 질문입니다.

**저렴한 점검, 순서대로:**
1. **타임라인 조인.** 변화점 윈도우(`root-cause-analysis.md` § 1) 안에
   게이지 / 보정 / 검사-레시피 이벤트가 있었는가? 계측 이벤트가 이동과
   일치하면 공정이 아니라 그것을 선도 용의자로 취급하세요.
2. **기준 샘플 재측정.** 보관된 known-good 부품을 현재 게이지로 재측정.
   *그것들*이 이제 이동해서 읽히면 게이지가 움직인 것입니다.
3. **게이지 R&R (반복 측정이 있으면).** 총 변동을 부품 간 vs 측정
   (반복성 + 재현성)으로 분해. `%GRR = σ_measurement / σ_total`와
   구별 범주 수 `ndc = 1.41 · σ_part / σ_gauge`를 보고하세요.
   경험칙: **%GRR < 10% 양호, 10–30% 한계, > 30% 게이지 부적합** —
   공정 전에 계측을 조사하세요.

```python
# 교차 operator×part 연구에서 %GRR (분산 성분 스케치)
import statsmodels.formula.api as smf
m = smf.ols("measure ~ C(part) + C(operator) + C(part):C(operator)", data=g).fit()
aov = sm.stats.anova_lm(m, typ=2)
# σ² 성분 → 반복성(잔차), 재현성(operator+상호작용),
# 부품 간(part). %GRR = sqrt(var_rr) / sqrt(var_total).
```

MSA가 신뢰할 수 없으면 **멈추세요** — 노이즈가 많은 게이지에 대한
어떤 공통성이나 DiD도 진짜 원인을 내놓지 못합니다.

## 파레토: 무엇부터 해결할 것인가

특정 원인에 파고들기 전에, 줄이려는 손실의 누적 분포를 그리세요. 80/20
법칙이 대체로 성립합니다: **실패 모드의 20%가 손실의 80%를
차지합니다.** 분석가 주의를 상위 20%에 배분하는 것이 어떤 RCA 프로그램
에서도 가장 큰 효율 개선입니다.

```python
pareto = (df.groupby("failure_mode")["cost_dollars"]
            .sum()
            .sort_values(ascending=False)
            .to_frame(name="total"))
pareto["cum_pct"] = pareto["total"].cumsum() / pareto["total"].sum() * 100
top20 = pareto[pareto["cum_pct"] <= 80]

print(f"상위 {len(top20)} / 전체 {len(pareto)} 실패 모드 = 손실의 80%")
print(top20)
```

**비용 차원을 신중히 선택하세요.** 비용 = 자본 손실은 달러, 사이클 타임
손실은 시간, 수율 손실은 결함 수, 신뢰성은 사건 수. 결함 수 기준
파레토와 달러 기준 파레토는 자주 순위가 다릅니다 — 드물지만 치명적인
모드가 달러를 지배하고, 흔한 경미한 모드가 수를 지배할 수 있습니다.
다를 때는 둘 다 보고하세요.

**시각적 참조:** 내림차순 파레토 막대 차트 + 누적 퍼센트 보조축 —
전형적인 다이어그램. 80% 지점에 수평선을 그어 컷오프를 표시하세요.

## Is/Is-Not 분석 (Kepner-Tregoe)

원인을 브레인스토밍하기 전에 네 차원 — What, Where, When, How-big —
으로 **문제 범위를 정하고**, 각 차원에 대해 문제가 무엇**인지(IS)**와,
날카롭게, 무엇일 수 **있었지만 아닌지(IS-NOT)**를 기록하세요. IS-NOT
열이 분석의 핵심입니다: 원인 공간을 좁히고, 결정적으로 통계 도구의
**대조군을 정의**합니다.

| 차원 | IS | IS-NOT (그러나 그럴 수 있었던) |
|---|---|---|
| What | 어떤 결함 / 제품 / 특성 | *정상인* 유사 제품 |
| Where | 라인 3, 챔버 5, 웨이퍼 엣지 | 라인 1-2, 다른 챔버, 웨이퍼 중심 |
| When | 06-20 레시피 배포 이후 | 06-20 이전; 주말에는 아님 |
| How-big | 14% 결함률, +9pp | 50%는 아님; 단일 로트 스파이크는 아님 |

**왜 이것이 통계로 바로 이어지는가:**
- IS-NOT 집합은 공통성(`rca-commonality.md`)과 이중차분법
  (`rca-causal-analysis.md`)의 **대조 / 비교군**입니다. "라인 3은 나쁘고
  라인 1-2는 정상"은 정확히 DiD 처리/대조 분할입니다.
- 날카로운 Is/Is-Not 경계는 어골도 가지를 공짜로 죽입니다: 문제가
  **오직** 야간 시프트에만 있다면, 두 시프트에 걸친 자재 로트 원인은
  검정 없이 이미 반박됩니다.
- IS-NOT 열을 채울 *수 없는* 차원은 데이터 공백입니다 — Tier 2의
  "배제할 수 없는 사항"에 한계로 기록하세요.

Is/Is-Not은 파레토(*어떤* 문제인지 선택) 이후, 어골도(*왜*인지
브레인스토밍) 이전에 실행하세요 — 모호한 불만을 경계가 있는 검정 가능한
비교로 바꿉니다.

## 어골도 (이시카와) — 6M 분류

답이 아니라 후보 생성 도구입니다. 여섯 가지(6M) 가지가 가능한 원인
공간을 스팬합니다. 각 가지에서 브레인스토밍한 뒤 각 후보를 통계
검정에 넘깁니다. **아무 가지도 검증되지 않은 어골도는 RCA 발견이
아닙니다 — 화이트보드 스케치입니다.**

| 가지 | 예시 | 통계적 검증 방법 |
|---|---|---|
| **Man (인)** — 작업자, 시프트, 훈련 | 신규 작업자, 야간 시프트 | 시프트/작업자 공통성 + 케이스 믹스 경고 (`rca-commonality.md`) |
| **Machine (기계)** — 장비, 설비, 픽스처 | 챔버 5, 로봇 팔 | 장비별 공통성 (`rca-commonality.md`) |
| **Material (자재)** — 로트, 공급자, 소모품 | 공급자 배치, 웨이퍼 로트 | 로트 / 공급자 공통성 (`rca-commonality.md`) |
| **Method (방법)** — 레시피, 절차, SOP | 레시피 v3.2 배포 | 레시피 버전 DiD (`rca-causal-analysis.md`) |
| **Measurement (측정)** — 게이지, 캘리브레이션 | 드리프트된 프로브, 새 검사 레시피 | MSA / 게이지 R&R — 위 "게이지를 먼저 배제" 참조; 공정 가지들보다 *먼저* 검증 |
| **Milieu (환경)** — 환경, 습도, 온도 | 계절적 주변 조건 변화 | SPC 자기상관 + 공변량 통제 (`root-cause-analysis.md` § 2) |

검증 열이 어골도를 RCA로 만드는 것입니다. 팀이 검증된 가지 없이
어골도를 발표할 때, "이 여섯 중 어느 것이 가장 강한 가설이고, 어떤
공통성 / DiD / SPC 검정이 이를 죽일 수 있는가?"를 물으세요 — 그리고 그
검정을 먼저 실행하세요.

## 통계적 반증이 결합된 5-Why

고전적 5-Why 사슬 — "결함률이 상승. 왜? 레시피가 바뀜. 왜? 신규 작업자가
잘못 배포. 왜? 훈련이 급했음. 왜? 릴리스 데드라인. 왜? 불명확한 우선순위"
— 은 **각 '왜' 단계가 주장이 아니라 검증**될 때만 실질적입니다.

사슬의 각 단계는 인과 주장입니다:
- 1단계: 레시피 변경 → 결함률 상승 (DiD로 검정)
- 2단계: 신규 작업자 → 레시피 변경 (역할-타임스탬프 교차 점검)
- 3단계: 훈련 공백 → 잘못된 레시피 배포 (훈련 기록 vs 배포 로그 조인)
- 4단계: 데드라인 → 훈련 서두름 (일반적으로 통계 검정 불가, 휴먼 팩터)
- 5단계: 불명확한 우선순위 → 데드라인 잘못 설정 (조직적, 통계 아님)

사슬의 하단은 종종 통계 도메인을 벗어나 휴먼 팩터로 들어갑니다 —
괜찮지만, 명시적으로 그렇게 말해야 합니다. 그 경계 위의 모든 것은
검정이 붙어 있어야 합니다.

**반증 규칙:** 각 '왜' 단계에 대해, 그 주장을 *반박할* 통계 검정을
지명하세요. 검정이 존재하지 않으면 그 단계는 추측입니다 — 보고서에
그렇게 표시하고, 검정이 있는 어골도 가지에 매핑하여 계속하세요.

## 결합: 파레토 → 어골도 → 5-Why → 통계적 검증

정성 우선 파이프라인:

1. **MSA** — 게이지를 배제. 측정 시스템이 움직였다면 멈추고 계측을
   먼저 고치세요.
2. **파레토** — 손실의 가장 큰 몫을 차지하는 단일 실패 모드를 식별.
   80% 컷오프 아래는 모두 뒤로 미룸.
3. **Is/Is-Not** — What / Where / When / How-big 범위 설정; IS-NOT
   집합이 통계 검정의 대조군이 됩니다.
4. **어골도** — 그 실패 모드에 대해 6M 전반에서 후보 원인을
   브레인스토밍; Is/Is-Not 경계가 이미 반박하는 가지는 버림.
5. **5-Why** — 살아남은 상위 1-2개 후보를 골라 각각에 인과 사슬을 구축.
6. **통계적 검증** — 각 단계에 붙은 검정을 실행. 검증 가능한 모든
   단계가 반증을 견딘 사슬만 보고.

이 구조는 엔지니어에게 발견이 무엇인지 뿐 아니라 *왜* 발견을 신뢰해야
하는지도 제공합니다. Tier 2 보고서의 § 5 "배제할 수 없는 사항" 내용도
자연히 나옵니다 — 검정 불가능한 단계가 선언된 한계가 됩니다.

## 안티패턴

| 안티패턴 | 증상 | 해결 |
|---|---|---|
| 어골도를 답으로 발표 | 덱에 6가지 다이어그램, 검정 결과 없음 | 어골도는 후보 생성기. 발표 전 최소 상위 가지에는 통계적 검증을 붙이세요. |
| 반증 없는 5-Why | 5개의 주장 사슬, 어느 링크에도 검정 없음 | 각 단계는 그것을 반박할 통계 검정이 있어야 합니다. "휴먼 팩터" 경계 아래 단계는 예외 — 그렇게 표시하세요. |
| 아무 가지도 검증되지 않은 어골도 | 보고서에 붙여넣은 화이트보드 사진 | 최소 선도 가지의 검정은 실행하세요. 시간 제약이 있으면 검증된 가지만 발표하고 나머지는 "후속 후보"로 라벨링. |
| 잘못된 차원의 파레토 | 목표가 달러인데 결함 수로 순위 | 비용 차원을 명시하세요. 수와 달러가 다를 때 둘 다 보고. |
| 파레토를 완전히 건너뜀 | 처음 보고된 실패 모드에 딥다이브 | 항상 파레토 먼저. 들은 모드는 상위 5에도 없을 수 있습니다. |
| 게이지를 배제하지 않고 이동을 귀속 | "결함률이 급증" — 그러나 같은 날 프로브가 재보정됨 | MSA 점검을 먼저 실행. 변화점 윈도우 안의 계측 이벤트는 공정이 아니라 선도 용의자입니다. |
